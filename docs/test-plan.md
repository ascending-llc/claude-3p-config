# Test plan

Run this on each new platform, and again after changing the config schema or the generated policies. Run it twice: first with an administrator permission set to prove the configuration works, then with the permission set people will actually get, to prove its IAM policy is enough.

## Before you start

The original AS-1975 spec assigns the full regression checklist below by location. The separately authorized login-only checks recorded above cover a narrower scope.

- **Implementer in mainland China.** Run `make all`, `plutil -lint` on both generated `.mobileconfig` files, and decode the Windows `.reg` with `iconv -f UTF-16 -t UTF-8`. Keep these checks offline. Do not run `aws sso login --profile CCWB`, send a Codex prompt, or open Claude Desktop or Claude Code with the policy installed. This restriction also applies while using a VPN.
- **Optional status-only check.** Codex C1 may be checked on a machine with no `[profile CCWB]` in `~/.aws/config` and no other AWS credentials available. Inspect `/status` only.
- **US-based tester.** Remove older profiles before installing the new identifiers, then run D1–D4, T1–T4, C1, C2 and C9 on macOS and Windows. Include a Windows machine with WSL2 for D4. Confirm the deployed Jarvis auth-server has the static client before connector testing.

The existing T1 and T2 commands, D3 and C2, and the prompt in C9 invoke models. Follow the location split for these checks. Record the platform and exact tests completed.

- **Codex setup program.** Build the `.exe` with a test `config/config.json` using the [admin guide's build commands](codex-setup-guide.md#4-build). Use a disposable Windows test machine for S1–S8. The mainland China implementer must not accept the optional AWS sign-in prompt; US-based testers perform AWS sign-in and the C2/C10 model checks in S1/S7. Container builds and code-signing checks download tools or contact signing services; they do not invoke Bedrock.

- **Use a clean shell.** Exported `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` or `AWS_SESSION_TOKEN` override `AWS_PROFILE`.
- **Expect your own Claude Code to switch.** Once the policy is installed, every `claude` session for your user uses Bedrock, including ones already running (Claude Code re-reads managed settings periodically).
- **Use a browser that completes device sign-in.** On the tested Mac, one Chrome installation never sent the approval after "Confirm and continue", in every profile and in incognito, while Safari and a fresh Chrome profile worked.
